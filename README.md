# ototori（耳コピ練習アプリ）

ジャズソロの耳コピを補助する PWA。音源ファイルを読み込み、テンポを落として区間ループ再生し、
「アンカー送り」でフレーズごとに区間を送りながら曲を頭から潰していく。

**公開URL: <https://ototori.netlify.app/>**

- 100% クライアント完結（音源は端末外に送信しない）
- スタック: Vite + React + TypeScript、Web Audio API、波形は Canvas 自前描画
- テンポ変更（ピッチ維持）: Rubberband(WASM) の事前レンダリング方式
- PWA（ホーム画面に追加してオフラインで使える）／再生中は画面が消灯しない
- ホスティング: Netlify（main への push で自動デプロイ）

## 使い方

**探索モード**と**練習モード**を行き来しながら、フレーズ単位で区間を送っていく。

1. 音源を読み込むと **探索モード**。再生すると起点から素通しで流れる（常に等速）
2. フレーズの切れ目で **「区切る」** → その位置が終点になり、区間が即ループ再生される（**練習モード**）
3. 練習モードでテンポを落として（ピッチは維持される）反復練習する
4. 吹けたら **「次へ」** → 今の終点が新しい起点になり、そこから素通し再生を再開
5. **「戻る」** で前の区間に戻る／**「取り直す」** で終点を打ち直す

### 区間の記録

あとで戻りたい区間は、番号を付けて保存できる。

- 練習モードの **「記録」** で、今の区間とテンポを保存する（同じ内容がすでにあれば「#3 記録済み」と表示される）
- メニュー（≡）の「記録」から番号を押すと、その区間とテンポで練習を再開する
- ✕ で 1 件削除、「全て削除」でそのファイルの記録をすべて削除する。削除で空いた番号は再利用せず、記録が 0 件になると #1 に戻る
- 記録はファイルごとに端末に残り、同じファイルを開き直すと表示される。ファイルはサイズと内容で見分けるので改名しても引き継がれるが、再エンコードすると別のファイルになる

> 記録はブラウザの `localStorage` に保存する（音源は保存しない）。ブラウザのデータを消すと記録も消える。
> iOS の Safari ではしばらく開かないと消えることがあるので、ホーム画面に追加して使うのがよい。

### 波形の操作

波形の**上半分は区間（起点・終点）**、**下半分は再生位置**を操作する。
各バーは掴める側の半分が実線、反対側が点線で表示され、つまみ（区間＝丸、再生位置＝ひし形）も掴める側にある。
触っている間は反対側の半分が暗くなり、つまみが「起点」「終点」・再生位置の時刻のラベルに変わる。

| 操作 | 上半分 | 下半分 |
| --- | --- | --- |
| バー付近をドラッグ | 起点・終点を微調整 | 再生位置を移動（再生中は離すとそこから再開） |
| それ以外をドラッグ | スクロール（パン） | スクロール（パン） |
| タップ | 探索＝起点を移動 / 練習＝その位置へシーク | その位置へシーク |
| ピンチ（PC: Ctrl+ホイール） | 拡大・縮小 | 拡大・縮小 |

> 再生位置は起点より前には動かせない（練習モードでは区間内に限る）。
>
> 起点のつまみは右向き三角で終点のつまみより上に、終点のつまみは左向き三角で下にある。2 本のバーが近いときは、触った高さに近いほうを掴む。
>
> 曲の先頭と末尾の外側には余白がある（幅はセーフエリア＋つまみの半径）。ノッチやベゼルがある端末でも、端のつまみを掴める。

メニュー（≡）から、テンポ・区間フィット・全体表示・ファイルの読み込みができる。

> 横置き前提のレイアウト。縦向きのときは回転を促すが、そのまま使うこともできる。
> なお iOS Safari は画面の向きのロックに対応していないため、向きを強制することはできない。

## インストール（ホーム画面に追加）

ブラウザでも使えるが、ホーム画面に追加すると全画面で起動し、オフラインでも動く。

**iPhone / iPad**（自動の案内は出ないので手動で追加する）

1. **Safari** で <https://ototori.netlify.app/> を開く
2. 下部の共有ボタン（□に↑）をタップ
3. メニューを下にスクロールして **「ホーム画面に追加」**
4. 名前を確認して「追加」

**Android**（Chrome）

アドレスバーのメニューから「アプリをインストール」、または表示されるインストールの案内に従う。

> アイコンや名前を変更した場合、**追加済みのものは自動更新されない**。一度削除してから追加し直す。

## 開発（Docker）

ローカルに Node を入れず、コンテナ内で実行する。`node_modules` は名前付きボリュームに隔離。

```sh
docker compose up        # http://localhost:5173
docker compose down      # 停止
```

初回は `npm install` が走るため少し時間がかかる。以降はソースをホストで編集すると HMR で即反映される。
スマホの実機で確認する場合は `http://<PC の LAN IP>:5173` を開く。

```sh
docker compose exec dev npm run typecheck   # 型チェックのみ
docker compose exec dev npm run build       # 型チェック + 本番ビルド(dist/)
```

## デプロイ（Netlify）

`netlify.toml` に設定済み（ビルド `npm run build` / 公開 `dist`）。GitHub 連携で main への push を自動デプロイする。

1. Netlify で「Add new site → Import an existing project」から本リポジトリを選択
2. ビルド設定は `netlify.toml` が読まれるのでそのまま作成
3. 以降 main にマージされると自動でデプロイされる

Service Worker と manifest は `no-cache`、ハッシュ付きアセットは長期キャッシュするようヘッダを設定してある。

> PWA としてのインストールやオフライン動作の確認は HTTPS が必要なため、デプロイ後の URL で行う。
